# CyberMac safety model

CyberMac is designed around manual privileged writes and sidecar-first installation. The SwiftUI app must not run privileged commands, shell commands, admin AppleScript, or helper tools.

## No automatic privileged writes

CyberMacApp does not run `sudo`. It does not call `Process`, shell binaries, `osascript`, admin AppleScript, or privileged helper APIs. When bundle files need to change, CyberMac prepares commands for the user to inspect and run manually in Terminal.

## Manual sudo command design

Activation, restore, and input patch flows generate copy commands instead of executing them. The user remains responsible for reviewing and running those commands.

## Sidecar-first installation

Supported mods are installed under:

```text
~/Library/Application Support/CyberMac
```

CyberMac keeps mod files, manifests, generated cache output, runtime imports, diagnostics, and temporary activation files outside the Cyberpunk app bundle unless the user manually applies a prepared copy command.

## Backup and verification

Before preparing a command that would replace a bundle file, CyberMac stores a backup record. After the user runs a manual copy command, CyberMac verifies the target with SHA-256 and reports whether the expected output is active.

## Input XML patching with markers

Input XML patching writes generated XML files in the CyberMac sidecar first. CyberMac uses markers for generated input sections so it can detect existing CyberMac-managed changes and avoid blindly stacking duplicate patches.

## Unsupported dependency policy

CyberMac intentionally rejects or marks unsupported framework stacks conservatively. Do not force unsupported dependency chains such as Cyber Engine Tweaks, RED4ext, Codeware, ArchiveXL, TweakXL, DLL / ASI mods, REDmod-only mods, or framework-dependent archive mods.

## If activation fails

Run:

```bash
swift run cybermac doctor
swift run cybermac cache-status
swift run cybermac activate --verify
```

If verification fails, do not keep copying random files into the app bundle. Use the backup and restore commands generated by CyberMac, then verify the restore.

## Restore script cache

List backups, prepare a restore command, run the printed command manually, then verify:

```bash
swift run cybermac list-backups
swift run cybermac restore --dry-run <backup-id>
swift run cybermac restore <backup-id>
# run printed sudo command manually
swift run cybermac restore --verify <backup-id>
```

If you want to restore the latest known vanilla cache, use:

```bash
swift run cybermac restore-vanilla --dry-run
swift run cybermac restore-vanilla
# run printed sudo command manually
swift run cybermac restore-vanilla --verify
```

## Restore input config

List input backups, prepare a restore command, run the printed command manually, then verify:

```bash
swift run cybermac list-input-backups
swift run cybermac restore-input-config --dry-run <backup-id>
swift run cybermac restore-input-config <backup-id>
# run printed sudo commands manually
swift run cybermac restore-input-config --verify <backup-id>
```

## What not to do

- Do not force unsupported framework mods.
- Do not manually copy random files into the app bundle.
- Do not refresh base cache from a CyberMac-generated bundle unless intentionally restoring or confirming an update.
